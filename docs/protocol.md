# Orbit WebSocket Communication Protocol (v1.0)

> This document is the source of truth for Orbit client implementations (including Flutter mobile apps, CLI clients, and external developer integrations).

---

## 1. Overview & Transport

* **Transport**: Standard WebSocket (`ws://` or `wss://`)
* **Default Port**: `4371`
* **Bind Address**: `0.0.0.0` (accessible across the local Wi-Fi / LAN network)
* **Message Encoding**: UTF-8 JSON text frames
* **Maximum Message Size**: 65,536 bytes (64 KB)

---

## 2. Message Envelopes

Every message transmitted over the WebSocket belongs to one of three categories:
1. **Request** (`type: "request"`) — initiated by client, expects an asynchronous response matching `id`.
2. **Response** (`type: "response"`) — returned by the agent in response to a request.
3. **Event** (`type: "event"`) — unidirectional notification (e.g. handshake welcome, pairing confirmation).

### 2.1 Request Envelope
```json
{
  "id": "req_001",
  "type": "request",
  "action": "system.info",
  "payload": {}
}
```

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | String | Unique request identifier generated by the client to correlate asynchronous responses. |
| `type` | String | Must always be `"request"`. |
| `action` | String | The operation to execute (e.g. `"ping"`, `"pairing.verify"`). |
| `payload` | Object | Action-specific parameters (defaults to `{}`). |

### 2.2 Response Envelope (Success)
```json
{
  "id": "req_001",
  "type": "response",
  "action": "system.info",
  "success": true,
  "payload": { ... }
}
```

### 2.3 Response Envelope (Error)
```json
{
  "id": "req_001",
  "type": "response",
  "action": "system.info",
  "success": false,
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Device must be paired to access this resource."
  }
}
```

### 2.4 Event Envelope
```json
{
  "type": "event",
  "event": "device.paired",
  "payload": { ... }
}
```

## 3. Connection Lifecycle & Pairing Flow

```
Mobile Client                                            Orbit Desktop Agent
     │                                                            │
     │ ─────────────── 1. WebSocket Connect ─────────────────────►│
     │                                                            │
     │◄─────────────── 2. Event: "welcome" ───────────────────────│
     │                                                            │
     │ ─────────────── 3. Request: "ping" ───────────────────────►│
     │◄─────────────── 4. Response: "ping" (timestamp) ───────────│
     │                                                            │
     │ ─────────────── 5. Request: "pairing.verify" ─────────────►│
     │                    payload: { code, name, platform }       │ (Validates 6-digit code)
     │                                                            │ (Assigns deviceId)
     │◄─────────────── 6. Response: "pairing.verify" ─────────────│ (Marks session paired)
     │                    payload: { paired: true, deviceId }     │
     │                                                            │
     │◄─────────────── 7. Event: "device.paired" ─────────────────│
     │                                                            │
     │ ═══════════════ AUTHENTICATED SESSION ESTABLISHED ════════ │
     │                                                            │
     │ ─────────────── 8. Request: "system.info" ────────────────►│
     │◄─────────────── 9. Response: "system.info" ────────────────│
```

### 3.1 QR Code Pairing Payload (`orbit://pair/v1`) (Milestone 08.6)

The Orbit Desktop application displays a pairing QR code that mobile clients can scan to automatically prefill connection settings and pairing codes:

```
orbit://pair/v1?host=192.168.1.50&port=4371&code=842917&expires=1788472615
```

| Parameter | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `host` | String | Yes | Workstation LAN IP address or hostname. |
| `port` | Integer | Yes | Agent WebSocket listening port (default: 4371). |
| `code` | String | Yes | 6-digit numeric temporary pairing code. |
| `expires` | Integer | Optional | Unix epoch timestamp in seconds when pairing code expires. |

**Security Rules:**
- **Zero Secrets**: The QR payload MUST NEVER contain permanent API keys, OpenCode auth tokens, SSH keys, or passwords.
- **Short-Lived**: QR codes only embed the temporary 6-digit pairing code and respect the desktop TTL (10 minutes).
- **Validation**: The mobile client strictly parses the `orbit` URI scheme and `pair/v1` path before presenting connection parameters.

## 4. Supported Actions & Specifications

### 4.1 `ping`
* **Access Level**: Public (Pre-pairing allowed)
* **Description**: Verifies liveness and measures network round-trip time.

**Request:**
```json
{
  "id": "req_ping_01",
  "type": "request",
  "action": "ping",
  "payload": {}
}
```

**Response:**
```json
{
  "id": "req_ping_01",
  "type": "response",
  "action": "ping",
  "success": true,
  "payload": {
    "timestamp": 1788472015
  }
}
```

---

### 4.2 `pairing.verify`
* **Access Level**: Public (Pre-pairing allowed)
* **Description**: Submits the 6-digit human-readable pairing code displayed on the Orbit Desktop UI.
* **Security Rules**:
  - Maximum 5 failed attempts allowed before triggering `RATE_LIMITED`.
  - Pairing codes expire after 10 minutes (TTL).
  - Pairing codes are never logged to console or disk.
  - Can be populated automatically via the `orbit://pair/v1` QR code.

**Request:**
```json
{
  "id": "req_pair_01",
  "type": "request",
  "action": "pairing.verify",
  "payload": {
    "code": "842917",
    "name": "Alex's iPhone",
    "platform": "ios",
    "deviceId": "dev_stable_installation_id"
  }
}
```

### 4.2.1 `session.resume` (Milestone 08.6)
* **Access Level**: Public (Pre-pairing allowed with existing paired device identity)
* **Description**: Allows a previously paired client to reconnect seamlessly on app resume or socket reconnect without prompting for pairing code or creating duplicate device entries.
* **Security Rules**:
  - Requires a valid, previously verified `deviceId`.
  - If the device was previously paired on an old connection, the old socket is gracefully retired and the new connection immediately inherits authenticated paired status.

**Request:**
```json
{
  "id": "req_resume_01",
  "type": "request",
  "action": "session.resume",
  "payload": {
    "deviceId": "dev_5e8f2541c74941e58c45358463bfeb6b"
  }
}
```

**Response (Success):**
```json
{
  "id": "req_resume_01",
  "type": "response",
  "action": "session.resume",
  "success": true,
  "payload": {
    "resumed": true,
    "deviceId": "dev_5e8f2541c74941e58c45358463bfeb6b"
  }
}
```

**Response (Device Not Paired):**
```json
{
  "id": "req_resume_01",
  "type": "response",
  "action": "session.resume",
  "success": false,
  "error": {
    "code": "NOT_PAIRED",
    "message": "Device is not currently paired with this agent."
  }
}
```


**Response (Success):**
```json
{
  "id": "req_pair_01",
  "type": "response",
  "action": "pairing.verify",
  "success": true,
  "payload": {
    "paired": true,
    "deviceId": "dev_5e8f2541c74941e58c45358463bfeb6b"
  }
}
```

**Broadcast Event Emitted:**
```json
{
  "type": "event",
  "event": "device.paired",
  "payload": {
    "deviceId": "dev_5e8f2541c74941e58c45358463bfeb6b",
    "name": "Alex's iPhone",
    "platform": "ios",
    "pairedAt": 1788472015
  }
}
```

**Response (Invalid / Expired Code):**
```json
{
  "id": "req_pair_01",
  "type": "response",
  "action": "pairing.verify",
  "success": false,
  "error": {
    "code": "INVALID_PAIRING_CODE",
    "message": "The pairing code is invalid or expired."
  }
}
```

* **Description**: Resumes an existing OpenCode session using its persistent session ID.
* **Payload**:
  ```json
  {
    "openCodeSessionId": "ses_...",
    "projectPath": "/path/to/project",
    "prompt": "Follow up question",
    "agent": "plan",
    "readOnly": true
  }
  ```
* **Response**: `{ "taskId": "<uuid>", "status": "queued" }`

### 4.7.3 `ai.task.cancel`
* **Access Level**: Paired Only
* **Description**: Cancels a running AI task via graceful SIGINT signal to OpenCode.
* **Payload**: `{ "taskId": "<uuid>" }`
* **Response**: `{ "taskId": "<uuid>", "status": "cancelled" }`

### 4.7.6 AI Events
Orbit streams live normalized events for AI tasks:
* `ai.task.created`: Dispatched when task is queued.
* `ai.task.started`: Dispatched when child process starts.
* `ai.task.activity`: Dispatched for real-time structured activities (commands, file operations, tool lifecycle).
* `ai.task.response`: Dispatched for streaming assistant response text chunks (`delta`).
* `ai.task.output`: Dispatched for user-visible stdout chunks.
* `ai.task.completed`: Dispatched when task succeeds.
* `ai.task.failed`: Dispatched when task fails.
* `ai.task.cancelled`: Dispatched when task is stopped by user.
